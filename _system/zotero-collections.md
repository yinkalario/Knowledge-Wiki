# Zotero collection configuration

> Local configuration for WORKFLOW sections 15–17, not a second operational protocol. Only read for Zotero ingest/classification maintenance. Projects and Archive are user-managed and protected, including all descendants.

## Assignment rules

- Topics answer what research problem a paper addresses; Methods identify techniques central to its contribution. Prefer the narrowest suitable existing category, but do not add ancestors solely for tree navigation. Multiple independent memberships are allowed.
- Preserve existing memberships. Ordinary ingest may add Topics/Methods memberships and remove only the verified Inbox membership after completion. Never replace all memberships or edit Projects/Archive.
- A reusable missing category may be created under Topics or Methods after a synonym/scope check. Record its key, parent and boundary. Existing-category rename/move/merge/split/delete requires a concrete approved plan and reevaluation of affected old items.
- Classify from the main contribution, not isolated keywords. Use broad scope when finer evidence is unavailable; when even the broad scope is unclear, leave pending. An incidental neural architecture or training optimizer is not a Methods assignment.
- Explicit user corrections take precedence; record persistent exceptions below. Do not infer project membership or ask for project descriptions.
- The managed tree below is a last-verified baseline. Check live keys, names and ancestry before writing. Record approved rule changes with a new revision and a log entry; never overwrite unreviewed structural differences.
